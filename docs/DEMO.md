### 2.3 结果分析

**为什么最优解是「两个汉堡」而不是「汉堡 + 薯条 + 可乐」？**

按热量密度排序：

| 商品 | 价格 | 热量 | 密度 |
| --- | ---: | ---: | ---: |
| 香芋派 | ¥8.00 | 232 | 29.00 |
| 脆薯饼 | ¥7.00 | 146 | 20.86 |
| 汉堡包 | ¥9.00 | 248 | 27.56 |
| 吉士汉堡包 | ¥11.00 | 294 | 26.73 |
| 小薯条 | ¥8.00 | 210 | 26.25 |
| 圆筒冰淇淋 | ¥4.00 | 93 | 23.25 |
| 中薯条 | ¥13.50 | 289 | 21.41 |
| 双层吉士汉堡 | ¥18.00 | 429 | 23.83 |
| 香芋派 | ¥8.00 | 232 | 29.00 |
| 可乐中杯 | ¥9.50 | 147 | **15.47** ⚠️ |

**关键发现：可乐中杯是全表密度最低的选项（15.47 kcal/元）。**

- 方案「汉堡 + 薯条 + 可乐」：¥9 + ¥13.5 + ¥9.5 = ¥32 → **超预算**，根本不可行
- 若强行压到 20 元，只能「汉堡包 + 可乐中杯」= ¥18.5 / **395 kcal**
- 而最优解「吉士汉堡包 + 汉堡包」= ¥20 / **542 kcal**

**同样 20 元，相差 147 kcal（+37%）。**

这就是算法的价值——**人脑会本能地想要「有吃有喝」，
但数学告诉你，把买可乐的钱换成第二个汉堡，能多吃 100 kcal。**

## 四、容错验证

| 场景 | 输入 | 行为 |
| --- | --- | --- |
| 空菜单 | `blocks = []` | 返回空列表，不崩溃 |
| 预算过小 | 唯一商品 ¥30，预算 ¥20 | 返回空列表 |
| 全 0 热量 | 所有商品热量为 0 | 返回空列表（目标函数无意义） |
| 免费商品 | 价格 0 但热量极高 | 排除出候选（避免除零与不合理结果） |
| 负热量脏数据 | `乙,0,0,-5` | 归零处理，不污染目标函数 |
| 营养表缺失商品 | 商品名查不到 | 热量记 0 + 输出告警 |
| 门店歇业 | `code 600057` | 提示换门店/时段，不伪造数据 |
