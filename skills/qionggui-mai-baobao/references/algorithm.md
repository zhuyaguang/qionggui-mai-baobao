# 求解算法详解

## 1. 问题定义

给定一组候选商品（每个商品有价格 `p_i` 与热量 `k_i`）和预算 `B`，
求一个子集 `S`，使得：

```
maximize  Σ_{i∈S} k_i
subject to Σ_{i∈S} p_i ≤ B
```

这在形式上是一个 **0/1 背包问题**，属于 NP-hard。

## 2. 为什么不能直接用经典背包

经典 0/1 背包假设所有物品**相互独立**。但麦当劳菜单不满足这个假设：

```
超值套餐 A（¥20.00，含巨无霸 + 中薯 + 中可）
├── 巨无霸     也可以单点 ¥22.00
├── 中薯条     也可以单点 ¥13.50
└── 可乐中杯   也可以单点 ¥9.50
```

如果把套餐 A 拆成三个子项放进背包，求解器会算出
「套餐 A + 巨无霸」这种**现实中并不存在的组合**——因为你不可能
既买了一份含巨无霸的套餐、又把它里面的巨无霸再单点一次（实际是买两份，
但如果求解器认为价格只算一次，就是**伪最优解**）。

更隐蔽的错误是**重复计数**：套餐里的巨无霸被算作免费赠送。

## 3. 解决方案：候选块（Block）+ 互斥剪枝

### 3.1 候选块模型

把菜单分成两类**不可再拆**的块：

| 块类型 | 来源 | 说明 |
| --- | --- | --- |
| `item` | 独立单品 | 菜单里直接可单点的商品 |
| `combo` | 套餐整体 | **原子块，绝不再拆分** |

关键规则：**套餐永远作为一个整体参与求解，其子项不单独入池**。

### 3.2 互斥关系

即使套餐不拆分，仍可能出现「套餐 A + 巨无霸」这种组合。
这里有两种语义，必须区分清楚：

- **语义 1（允许）**：用户买了套餐 A，**额外**再买一份巨无霸。
  这在现实中完全合法（就是两份巨无霸），价格应算 `¥20 + ¥22`。
- **语义 2（禁止）**：求解器把套餐 A 内部的巨无霸**当成免费**，
  同时又"单点"一次，导致重复计数。

本求解器采用**语义 1**，但通过以下方式杜绝语义 2：

1. 套餐作为原子块，其内部分量**永不单独出现在候选池**（除非门店
   确实把它列为单点商品）；
2. 当某单品名称恰好等于某套餐的子项名时，建立**互斥标记**
   （`Block.conflicts`），保证二者不同时被选。

> 互斥的判定在 `_add_conflict()` 中双向写入，
> 求解时用 `all(c not in chosen for c in conflicts_idx[i])` 一次性检查。

### 3.3 热量归属

套餐热量按以下优先级确定：

1. **整名命中营养表** —— 最准确，直接用官方值；
2. **子项热量求和** —— 从 `roundList` / `comboItemList` 里抽出子项名，
   逐个查表后相加；
3. **名称组合启发式** —— 按 `COMPOSITION_HINTS` 词表把「巨无霸套餐」
   拆成「巨无霸 + 中薯 + 中可」，并对缺失子项补一个保守余量。

第 3 级是**兜底**，结果会偏保守（宁可低估不虚高），并会在输出里
提示用户以官方数据为准。

## 4. 求解：分支限界

### 4.1 为什么需要剪枝

候选块数量级在 100–300。朴素枚举是 `2^300`，不可行。

但背包问题有很好的**松弛上界**：允许「切分」物品（分数背包），
可以用贪心在 `O(n)` 内算出上界。

### 4.2 算法流程

```
1. 按热量密度 k_i / p_i 降序排序
2. DFS 搜索：
   for each block i:
       if upper_bound(i, remain) <= best_kcal: 剪枝（整枝跳过）
       分支 A：选入 i（若价格允许且不与已选块互斥）
       分支 B：跳过 i
3. 记录 top-k 个不同组合
```

### 4.3 上界函数

```python
def upper_bound(i, remain, cur_kcal):
    """从第 i 个块开始，按密度降序装填的分数背包松弛。"""
    ub, rem = float(cur_kcal), float(remain)
    for j in range(i, n):
        if cands[j].price <= rem:
            ub += cands[j].kcal
            rem -= cands[j].price
        else:
            ub += cands[j].kcal * (rem / cands[j].price)  # 允许分数
            break
    return ub
```

由于块已按密度降序排列，这个上界是**紧的**——大部分分支会在
前几层就被剪掉，实测 60 个候选块在毫秒级完成。

### 4.4 时间预算保护

`time_budget_ms` 默认 20000ms。搜索过程中每 4096 次迭代检查一次
deadline，超时抛出 `TimeoutError`，返回当前已找到的最优解。
这保证了对恶意/异常数据的鲁棒性——**永不卡死**。

## 5. 正确性验证

`tests/test_solver.py` 中 `test_matches_brute_force_random_small`
用随机数据（3–11 个块，60 组）把分支限界的结果与**暴力枚举**对照，
断言两者最大热量完全一致。这是算法正确性的核心证据。

## 6. 复杂度

| 场景 | 复杂度 |
| --- | --- |
| 排序 | `O(n log n)` |
| 最坏情况 | `O(2^n)`（但剪枝后实际接近 `O(n log n)`） |
| 空间 | `O(n)`（DFS 栈 + top-k 结果） |

## 7. 可扩展方向

- **多目标优化**：当前只最大化热量。可扩展为
  `α·热量 − β·钠含量 − γ·脂肪` 的加权目标，
  适配健身人群（参考营养表的 `sodium` / `fat` 字段）。
- **蛋白质约束**：营养表含 `protein`，可支持「20 元吃到最多蛋白质」。
- **券后最优**：把 `available-coupons` 的券纳入求解，
  券后价格可能改变最优组合（某些券只对特定商品生效）。
